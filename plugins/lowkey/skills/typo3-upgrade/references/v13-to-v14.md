# TYPO3 13 to 14

Note: Every item in this file stays `unverified` until a real 13 to 14 run confirms it. Check each fact against the TYPO3 core changelog before you rely on it. Both changelog numbers below (#107945 and #107047) need a check against the changelog.

Read this file for every stage group of the rung 13 to 14 (A, B, C+D, E). The target is TYPO3 14.3 LTS. This file names no PHP minimum for 14. Read it from the TYPO3 14 system requirements and treat it as `unverified`. Binding rules (command classes, snapshots, folders, outcomes) live in `process.md`. Topic knowledge lives in `database.md`, `composer.md`, `schema-and-wizards.md` and `verification.md`. This file lists only the pitfalls of this rung.

## How to verify facts

With the MCP (`roadmap.md` says `available`), use `typo3_changelog_lookup` with the version and type filters for a deprecation sweep of the major. Without the MCP, read the TYPO3 core changelog on docs.typo3.org. Facts that you did not confirm in one of these sources stay `unverified`.

Extension major versions named below (Content Blocks 2.x, container 4.x, typo3-console 9.x) come from earlier practice. Check the current release, do not trust this number.

### FlexFormService removed
- Symptom: Code that calls `FlexFormService` fails after the jump.
- Detection: `grep -rn "FlexFormService" <own-extension-paths>`
- Fix: Replace it with `FlexFormTools`. Check the changelog entry for the changed method signatures. Do it in stage B if `FlexFormTools` offers the needed calls on 13 too.
- Proof: `grep` finds no hit in own code. The Extension Scanner shows no strong match for it. The affected output stays equal in the crawl diff.
- Stage: B
- Status: unverified
- Changelog: #107945 (unverified)

### ds_pointerField removed
- Symptom: FlexForm data structures no longer bind to their records. Fields in the backend show no FlexForm.
- Detection: `grep -rn "ds_pointerField" <own-extension-paths>` over TCA files.
- Fix: Bind the data structures through `columnsOverrides` per record type. Test each affected record type in the backend.
- Proof: Every FlexForm opens in the backend with all fields. An open-and-save row diff shows the same stored XML (`verification.md`).
- Stage: B
- Status: unverified
- Changelog: #107047 (unverified)

### ext_emconf.php and ext_tables.php deprecated
- Symptom: The deprecation log lists `ext_emconf.php` and `ext_tables.php` in Composer mode.
- Detection: List both files in each own extension. Read the deprecation log for the extension names.
- Fix: Move the content of `ext_tables.php` to the places that the changelog names for each kind of registration. Check the changelog before you remove `ext_emconf.php`. Do each move in its own commit.
- Proof: The deprecation log has no entry for both files. The backend modules and registrations of the extension work as before.
- Stage: B
- Status: unverified
- Changelog: none listed

### sys_template with clear=3 wipes Site Set TypoScript
- Symptom: TypoScript of a Site Set has no effect on pages that sit under a `sys_template` record with `clear=3`.
- Detection: Count `sys_template` records and list their `clear` values (counts only, no dumps in evidence).
- Fix: Move to Site Sets on 13 first, in stage A of this rung. Put the settings into `settings.yaml`. Avoid keeping `sys_template` records with `clear=3` next to Site Sets.
- Proof: A `ts-dump.php` before and after shows equal TypoScript (`verification.md`). The crawl diff is 0.
- Stage: A
- Status: unverified
- Changelog: none listed

### Site-scoped constants
- Symptom: Constants that must stay unset get values. Set-level constants lose against the defaults of `fluid_styled_content`.
- Detection: Compare the constants dump before and after (`ts-dump.php`). Look for constants that the old setup left empty.
- Fix: Put such constants into a site-scoped `constants.typoscript`. Set-level constants cannot override the defaults of `fluid_styled_content` here.
- Proof: The constants dump matches the baseline. The rendered output of the affected elements stays equal in the crawl diff.
- Stage: C+D
- Status: unverified
- Changelog: none listed

### content_defender replaced by core
- Symptom: `content_defender` has no release for 14. Allowed content types per column stop working after its removal.
- Detection: `grep -rn "allowed\.\|disallowed\." <backend-layout-paths>` and list the backend layouts that use the extension.
- Fix: Use the core options `allowedContentTypes` and `disallowedContentTypes` in the backend layout columns (core 14.1, check the changelog). Remove the extension after the replacement works. Removals run one by one (`schema-and-wizards.md`).
- Proof: Test the negative cases. A forbidden content type must not appear in the new-element wizard of its column, and the backend must reject it. Allowed types still appear.
- Stage: C+D
- Status: unverified
- Changelog: none listed

### Extension major versions
- Symptom: Extensions have no release for the target, and Composer cannot resolve the jump.
- Detection: Check each extension with `typo3_ter_lookup` (extension key from `composer.lock`) or Packagist (`composer.md` `### Lookups for public packages`). Earlier practice needed Content Blocks 2.x, container 4.x and typo3-console 9.x. Check the current release, do not trust these numbers.
- Fix: Raise each extension constraint in stage B, where the old version still accepts it. Record extensions without a release in `roadmap.md` and map each to a step (replace, remove, wait).
- Proof: The dry-run of the jump resolves. The inventory lists no extension without a release for the target in active use.
- Stage: B
- Status: unverified
- Changelog: none listed

### settings.php rewrite
- Symptom: The jump rewrites `settings.php`. Keys change or disappear. The file holds credentials.
- Detection: Copy the file before the jump. After the jump, diff the key paths of both files. Never print values.
- Fix: Compare key paths only (`process.md` `## Secrets`). Restore missing keys with `configuration:set` (main session command). Keep the copy outside the repository.
- Proof: The key path diff shows only expected changes. `configuration:show` on non-credential paths confirms them.
- Stage: C+D
- Status: unverified
- Changelog: none listed

## Ideas to verify

These ideas come from third-party notes. Confirm each one on a real run before you build a step on it.

### Rewrite rule for /typo3/
- Symptom: The backend under `/typo3/` fails or loops after the jump, because the web server rule for this path no longer fits.
- Detection: Open the backend login after the jump. Read the `.htaccess` of the project and compare its rewrite block for `/typo3/` with the file that the new core ships.
- Fix: Adapt the rewrite block of `.htaccess` to the version that the new core documents. Keep the change in its own commit.
- Proof: The backend login loads and a backend request returns the expected status.
- Stage: C+D
- Status: unverified
- Changelog: none listed

### Empty string before INT retypes
- Symptom: A schema change that turns a text column into an integer column fails or writes wrong values, because rows hold an empty string.
- Detection: Read the schema dry-run for retyped columns. For each one, count rows with `WHERE <field> = ''` (counts only).
- Fix: Convert the empty strings to `'0'` before the retype. This is a data write, so it is a main session command with a snapshot before.
- Proof: The count of empty strings is 0 before the schema change. The change runs without a failing statement.
- Stage: C+D
- Status: unverified
- Changelog: none listed

### Extbase fallbackType behavior in 14.3.x
- Symptom: Extbase maps records to the wrong model class after an update within 14.3.x, because the handling of `fallbackType` changed.
- Detection: `grep -rn "fallbackType" <own-extension-paths>` over TypoScript and TCA. Compare record types in the frontend before and after.
- Fix: Read the changelog of the installed 14.3.x release. Set the type mapping explicitly where the fallback decides the class.
- Proof: The affected plugins output the same records and the same classes in the crawl diff.
- Stage: B
- Status: unverified
- Changelog: none listed
