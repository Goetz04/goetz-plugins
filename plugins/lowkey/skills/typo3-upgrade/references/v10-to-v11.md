# TYPO3 10 to 11

Note: Every item in this file stays `unverified` until a real 10 to 11 run confirms it. The facts come from the TYPO3 core changelog, get.typo3.org and Packagist. Changelog numbers without a mark were opened on docs.typo3.org while this file was written. Numbers and claims marked `(unverified)` were seen only in a search excerpt or derived. Check them on the original page before you rely on them.

Read this file for every stage group of the rung 10 to 11 (A, B, C+D, E). The target is TYPO3 11.5. TYPO3 10.4 runs on PHP 7.2 to 7.4, TYPO3 11.5 on PHP 7.4.1 to 8.3 (get.typo3.org/version/10 and /version/11). Binding rules (command classes, snapshots, folders, outcomes) live in `process.md`. Topic knowledge lives in `database.md`, `composer.md`, `schema-and-wizards.md` and `verification.md`. This file lists only the pitfalls of this rung.

## How to verify facts

The MCP TYPO3/dev-companion covers 12.4, 13.4 and 14.3, not 10.4 or 11.5. For this rung, read the 11.x core changelog on docs.typo3.org, also when `roadmap.md` says `mcp: available`. An empty MCP answer for 11.x does not mean that no breaking change exists. Facts that you did not confirm on docs.typo3.org stay `unverified`.

## 11 as target

When the roadmap ends at 11, this rung is the target rung. Its extra acceptance demands a deprecation log without entries from own code (`roadmap-template.md`). Run a deprecation sweep of the 11.0 to 11.5 changelog against own code in stage B or E. Also read the B items of `v11-to-v12.md`, because several of them are deprecations of 11.

### Latest 10.4 patch release first
- Symptom: Fixes of stage B fail on the installed 10.4 patch level, or Composer cannot resolve a tool version. Example: `defined('TYPO3')` needs 10.4.11 or newer, typo3-console 6.x needs core 10.4.22 or newer.
- Detection: Read the version of `typo3/cms-core` in `composer.lock`. Check whether the package comes from Packagist or from the TYPO3 ELTS repository (`notification-url` and `dist` of the entry).
- Fix: Update to the latest 10.4 patch release before any other step of this rung. Composer commands are main session commands with `--no-scripts` (`composer.md`). Later 10.4 patches come only from the paid ELTS repository. ELTS packages carry no Packagist `notification-url`, so the skill classes them `private` and skips their lookups.
- Proof: `composer.lock` shows the new 10.4 patch level. The crawl diff against the previous baseline is 0 (`verification.md`).
- Stage: A
- Status: unverified
- Changelog: none listed

### PHP 7.4 bridge
- Symptom: Composer refuses the jump, or the site fails on the old or the new version. TYPO3 10.4 stops at PHP 7.4. TYPO3 11.5 starts at PHP 7.4.1.
- Detection: Read the PHP version from the DDEV config (`php_version`), from `config.platform.php` and `require.php` in `composer.json` and from the live system. The live system decides the go-live target.
- Fix: Switch DDEV to PHP 7.4 in stage A, on 10.4. Keep PHP 7.4 through the jump. Raise PHP only after 11.5 runs, in stage A of the rung 11 to 12 (`v11-to-v12.md`).
- Proof: The stage A crawl diff against the previous baseline is 0. `php -l` passes on own code (check command). The error log has no new lines.
- Stage: A
- Status: unverified
- Changelog: none listed

### DB server and Composer minimum for 11
- Symptom: TYPO3 11.5 refuses the DB server, or Composer cannot install 11.5.
- Detection: Read the DB type and version from `.ddev/config.yaml` (key `database`) and from the live system. TYPO3 11.5 needs MySQL 5.7.9 or newer or MariaDB 10.2.7 or newer (get.typo3.org/version/11). It needs Composer 2.1 or newer (docs.typo3.org, 11.5 system requirements). Read `plugin-api-version` in `composer.lock`. A value that starts with `1.` or a missing field points to Composer 1 (unverified). Never read `composer_version` from `.ddev/config.yaml`, because `process.md` `## Secrets` does not allow that key.
- Fix: Switch the DB server in stage A, on 10.4, before the jump (`database.md`). Switch to Composer 2.1 or newer in stage A. Both are main session commands with the snapshot `pre-<nn>-A-<k>` before a DB switch.
- Proof: The DDEV config shows the new DB version. A Composer run on 10.4 writes a `composer.lock` with a `plugin-api-version` of 2.x. The crawl diff of stage A is 0.
- Stage: A
- Status: unverified
- Changelog: none listed

### TYPO3_MODE guard on 10.4.11 or newer
- Symptom: The deprecation log on 11 lists `TYPO3_MODE`. On 12 the constant is gone (`v11-to-v12.md`).
- Detection: `grep -rn "TYPO3_MODE" <own-extension-paths>`
- Fix: Replace the guard line with `defined('TYPO3') or die();`. The constant `TYPO3` exists from 10.4.11 on (source of `SystemEnvironmentBuilder` in v10.4.11). So do it in stage B, after the patch update of this rung.
- Proof: The grep finds nothing in own code. `php -l` passes on each changed file (check command). The crawl diff is 0.
- Stage: B
- Status: unverified
- Changelog: Deprecation-92947

### Extbase plugin registration with class names
- Symptom: Plugins and backend modules of own extensions vanish or throw after the jump. 11.0 accepts only fully qualified controller class names.
- Detection: `grep -rn "configurePlugin\|registerPlugin\|registerModule" <own-extension-paths>`. Look for a vendor prefix in the extension name (`'Vendor.ExtName'`) and for short controller names as array keys (`'Blog' => 'list'`).
- Fix: Pass the extension name without vendor and use `BlogController::class` as array key. 10.0 introduced this form, so do it in stage B on 10.4.
- Proof: Every plugin renders in the crawl diff as before. Every backend module of the extension opens. The deprecation log on 10.4 has no entry for it.
- Stage: B
- Status: unverified
- Changelog: Deprecation-87550, Breaking-92609

### Fluid widgets removed
- Symptom: Templates that use `f:widget.paginate`, `f:widget.autocomplete` or own widgets fail after the jump.
- Detection: `grep -rn "f:widget\.\|AbstractWidgetController\|AbstractWidgetViewHelper" <own-extension-paths>` and the template paths of the site package.
- Fix: Replace pagination widgets with the pagination API (`QueryResultPaginator`, `ArrayPaginator`, `SimplePagination`). TYPO3 10.2 introduced it, so do it in stage B on 10.4. Replace other widgets with own view helpers or controller actions.
- Proof: The grep finds nothing. Every paginated list shows the same items and page links in the crawl diff, also on page 2 and later.
- Stage: B
- Status: unverified
- Changelog: Breaking-92529, Breaking-91473, Feature-89603 (unverified)

### Signal slots to PSR-14 events
- Symptom: Signal slots that 11.0 removed stop firing without an error. The Extbase signal slot dispatcher itself stays until 12.
- Detection: `grep -rn "SignalSlot\|connect(" <own-extension-paths>` and list every connected signal. Compare each with Breaking-91473 and the 11.0 changelog.
- Fix: Move each listener to the PSR-14 event that replaces the signal. TYPO3 10.0 introduced PSR-14 events, so do it in stage B on 10.4 where the event exists.
- Proof: The listener runs on 10.4 and 11.5, visible in the output or a log line. The deprecation log has no entry for the signal.
- Stage: B
- Status: unverified
- Changelog: Deprecation-90625 (unverified), Breaking-91473

### Removed functionality of 11.0
- Symptom: Own code fails after the jump on members that 11.0 removed, for example TSFE properties and methods, hooks, signals or `typolink.useCacheHash`.
- Detection: Run the Extension Scanner on 10.4 for each own extension (`verification.md` `## Extension Scanner`). The matchers of 10.4 know the deprecations of 10 that 11.0 removes. Read the 11.0 changelog index for the removals.
- Fix: Fix every strong match in stage B on 10.4. Fix weak matches after a manual check. Run the scanner again after the jump, because 11.5 brings new matchers.
- Proof: The scanner reports no strong match on 10.4 and on 11.5. The crawl diff after the jump shows only the expected diffs.
- Stage: B
- Status: unverified
- Changelog: Breaking-91473

### Bridge versions of extensions
- Symptom: Composer cannot resolve the jump, because an extension has no version for 11.5, or the jump changes code and core at the same time.
- Detection: List each extension with its raw `typo3/cms-core` constraint (`inventory.md`). Look for a version that allows `^10.4` and `^11.5`. Earlier lookups showed such lines for gridelements 11.x, container 1.6 and 2.x, mask 7.2 and news 9 and 10. Check the current release, do not trust these numbers.
- Fix: Raise each extension to its bridge version in stage B, on 10.4. Then the jump changes only the core. Extensions without a bridge version go into the jump step or get a replacement step.
- Proof: `composer.lock` on 10.4 lists bridge versions. The crawl diff of stage B shows only the expected diffs of the extension updates.
- Stage: B
- Status: unverified
- Changelog: none listed

### cms-about leaves composer.json
- Symptom: Composer cannot resolve the jump, because `typo3/cms-about` has no release for 11. The last release on Packagist is 10.4.37.
- Detection: `grep -n "cms-about" composer.json`
- Fix: Remove the package from `composer.json` in the jump step. 11.0 merged it into `EXT:backend`. Composer commands are main session commands with `--no-scripts` (`composer.md`).
- Proof: The jump resolves. `composer.lock` does not list the package. The backend about module still opens.
- Stage: C+D
- Status: unverified
- Changelog: Important-91888

### typo3-console major at the jump
- Symptom: Composer cannot resolve the jump, or console commands fail after it. typo3-console 6.x needs core 10.4, typo3-console 7.x needs core 11.5. No major covers both (Packagist, unverified for the current releases).
- Detection: `grep -n "helhum/typo3-console" composer.json composer.lock`. List the console commands that scripts, CI files and `.ddev` use.
- Fix: Raise the console constraint in the same Composer command as the core jump. Read `typo3 list` after the jump to see which provider supplies each command (`process.md` `## Command matrix`).
- Proof: `ddev exec vendor/bin/typo3 list` runs after the jump and shows the commands that the step brief uses.
- Stage: C+D
- Status: unverified
- Changelog: none listed

### Composer installers and PackageStates
- Symptom: Extensions change their active state after the jump. TYPO3 11.4 and later ignore `PackageStates.php` in Composer mode. Every extension that Composer installs is active.
- Detection: Compare the extensions in `composer.lock` with the active extensions of 10.4 in the backend extension manager. List extensions that Composer installs but 10.4 keeps inactive. Extensions stay in `typo3conf/ext` on 10 and 11. cms-core 10.4 and 11.5 allow `typo3/cms-composer-installers` ^2 or ^3. Version 4 exists only as release candidate, version 5 comes with 12.
- Fix: Remove inactive extensions from `composer.json` before the jump, or accept that they become active and test them. Keep the installers on ^2 or ^3 for this rung. Leave the installer change to the rung 11 to 12 (`composer.md`).
- Proof: The list of active extensions after the jump matches the planned list. The crawl diff shows no output of an extension that was inactive before.
- Stage: C+D
- Status: unverified
- Changelog: Important-95647, Deprecation-94996 (unverified)

### Wizards of 10 before the jump
- Symptom: Data stays unmigrated at a later rung. 11 still carries the wizards of 10 (unverified, derived from Breaking-91473, which removes only the wizards from 8 to 9), but 12 removes the wizards of older majors (`process.md` `## Hard gates`). Open wizards also mix two causes into the jump.
- Detection: Run `upgrade:list` on 10.4 before the jump (check command). The core keeps the wizards of two consecutive majors (docs.typo3.org, reference-coreapi 12.4, Upgrade). Core 10.4 documents `upgrade:run` on the CLI. Whether core 10.4 also offers `upgrade:list` is unverified. Read `typo3 list` for the provider. 10.4 offers wizards that install extensions which left the core in 10.0 (unverified). For each such wizard, check whether the site still uses the extension, for example by counting its records or plugins (counts only).
- Fix: Run every open wizard on 10.4, one per call (`schema-and-wizards.md`). Ask the user once per wizard that installs an extracted extension. Decline it only after a yes and record the decision in the step notes. If the site still needs the extension, plan its Composer package as a replacement step, or set the outcome to `blocked`. Never install TER extensions in Composer mode. Whether a declined wizard leaves the list is unverified. A wizard that stays in `upgrade:list` blocks the gate (`process.md` `## Hard gates`) and sets the outcome to `blocked`.
- Proof: `upgrade:list` on 10.4 is empty. The step notes name each declined wizard with the user's decision and the usage count. After the jump, run the wizards of 11 until `upgrade:list` on 11.5 is empty.
- Stage: C+D
- Status: unverified
- Changelog: none listed

### TypoScript and config proof on 10 and 11
- Symptom: The step needs a TypoScript equality proof, but `ts-dump.php` needs the include tree API of 12.
- Detection: `ts-dump.php` exits 2 on 10 and 11 (`verification.md` `## TypoScript proof`). `LocalConfiguration.php` stays in `typo3conf/` on 10 and 11. It moves only with 12 (Breaking-98319, unverified).
- Fix: Use crawl diffs as the only TypoScript proof on this rung. Keep the `secret_globs` for `typo3conf/LocalConfiguration.php` and `typo3conf/AdditionalConfiguration.php` (`process.md` `## Secrets`).
- Proof: The crawl diff after the jump matches the last 10.4 baseline except for the expected diffs.
- Stage: C+D
- Status: unverified
- Changelog: none listed
