# TYPO3 11 to 12

Read this file for every stage group of the rung 11 to 12 (A, B, C+D, E). The target is TYPO3 12.4. TYPO3 12 needs PHP 8.1 or newer. Binding rules (command classes, snapshots, folders, outcomes) live in `process.md`. Topic knowledge lives in `database.md`, `composer.md`, `schema-and-wizards.md` and `verification.md`. This file lists only the pitfalls of this rung.

## How to verify facts

With the MCP (`roadmap.md` says `available`), use `typo3_changelog_lookup` with the version and type filters for a deprecation sweep of the major. Without the MCP, read the TYPO3 core changelog on docs.typo3.org. Facts that you did not confirm in one of these sources stay `unverified`.

Items below carry `Status: practice` when a real upgrade from 11 to 14 used them. No item names a changelog number yet. Add one only after you confirmed it with the MCP or on docs.typo3.org.

### Config files move on first bootstrap
- Symptom: `LocalConfiguration.php` and `AdditionalConfiguration.php` disappear from `typo3conf/` and `settings.php` and `additional.php` appear in `config/system/`. Lockin's checks stop, because tracked files change.
- Detection: `git status` after the first bootstrap shows moved or deleted config files. Compare key paths only, never values (`process.md` `## Secrets`).
- Fix: Make the first bootstrap a main session command right after the Composer jump, with the snapshot `pre-<nn>-C+D-<k>` before it. Run any core CLI call, for example `vendor/bin/typo3 list` (class main session, because it moves files). Then commit or handle the moved files as the step brief states. Update the `secret_globs` for the new paths (`process.md` `## Secrets`).
- Proof: `config/system/settings.php` exists, the old files are gone, and a key path comparison shows the same keys as before.
- Stage: C+D
- Status: practice
- Changelog: none listed

### TYPO3_MODE removed
- Symptom: Extension files die or throw on load. The constant `TYPO3_MODE` no longer exists.
- Detection: `grep -rn "TYPO3_MODE" <own-extension-paths>`
- Fix: Replace the guard line with `defined('TYPO3') or die();`. This works on 11 and 12, so do it in stage B.
- Proof: The grep finds nothing in own code. `php -l` passes on each changed file (check command). The Extension Scanner shows no hit for it.
- Stage: B
- Status: practice
- Changelog: none listed

### typo3cms gone for core commands
- Symptom: `typo3cms` calls fail for core commands after the jump.
- Detection: `grep -rn "typo3cms" composer.json scripts .ddev` and in project docs and CI files.
- Fix: Call `vendor/bin/typo3` for core commands. The typo3-console version needs a check against the target major (check the current release, do not trust any number). Read `typo3 list` to see which provider supplies each command (`process.md` `## Command matrix`).
- Proof: `ddev exec vendor/bin/typo3 list` runs and shows the commands the step brief uses.
- Stage: C+D
- Status: practice
- Changelog: none listed

### INCLUDE_TYPOSCRIPT DIR:./ breaks silently
- Symptom: Pages render empty or with the message that the page is not configured. No error appears in a log.
- Detection: `grep -rn "INCLUDE_TYPOSCRIPT" <typoscript-paths>` and look for `DIR:./` and other relative sources. The value resolves against the public path.
- Fix: Replace each relative include with an `EXT:` path or with `@import`. Do it in stage B, so the code works on both versions.
- Proof: A crawl diff against the stage A baseline is 0 (`verification.md`). On 11 this crawl diff is the only TypoScript proof. After the jump, `ts-dump.php` before and after shows no difference beyond the expected diffs.
- Stage: B
- Status: practice
- Changelog: none listed

### TypoScript proof on 11
- Symptom: The step needs a TypoScript equality proof, but `ts-dump.php` does not run on 11.
- Detection: `ts-dump.php` needs TYPO3 12 or newer (`verification.md` `## TypoScript proof`).
- Fix: On 11, use crawl diffs as the only proof. Run `ts-dump.php` for the first time right after the jump, then again after each TypoScript change of the rung, and diff the files.
- Proof: The crawl diff of the last 11 baseline matches the post-jump crawl except for the expected diffs. The first `ts-dump.php` output sits in the evidence folder as the new reference.
- Stage: C+D
- Status: practice
- Changelog: none listed

### itemsProcFunc gets items by reference
- Symptom: Select fields lose items that an itemsProcFunc added. The return value no longer counts.
- Detection: `grep -rn "itemsProcFunc" <own-extension-paths>`, then open each method and check how it hands items back.
- Fix: Write the items into `$params['items']`, which the method receives by reference. Ignore the return value. This works on 11 and 12, so do it in stage B.
- Proof: The select field shows its items in the backend on both versions. An open-and-save row diff shows no changed values (`verification.md`).
- Stage: B
- Status: practice
- Changelog: none listed

### FlexForms lose the TCEforms wrapper
- Symptom: FlexForm fields vanish or render without labels. Selects show wrong items. File fields stop working.
- Detection: `grep -rln "TCEforms" <own-extension-paths>` over FlexForm XML files. Look for `items` written as old pairs and for `type=group` file fields.
- Fix: Remove the `TCEforms` wrapper. Write items as `label` and `value`. Use `type=file` for FAL fields. Do it in stage B where the old version accepts it, and check each form in the backend.
- Proof: Every FlexForm opens in the backend on 11 and 12 with all fields. An open-and-save row diff shows the same stored XML values (`verification.md`).
- Stage: B
- Status: practice
- Changelog: none listed

### CKEditor 5 preset
- Symptom: Rich text fields lose classes, styles, colors or headings. Stored content changes on save.
- Detection: Build an inventory of the stored RTE values over all fields that use the editor. List tags, classes and styles (counts only, no dumps in evidence). Check which fields force the preset `default`.
- Fix: Write a new YAML preset from the inventory. Round-trip all stored values through the editor and compare them. Register the project preset also under `default`, because fields that force `default` lose custom colors and headings otherwise.
- Proof: The round trip changes no stored value beyond the expected diffs. The crawl diff shows no change in rendered RTE content.
- Stage: C+D
- Status: practice
- Changelog: none listed

### EXT:form form-label and FluidEmail
- Symptom: Form markup changes and mails look different. The new form rendering writes `form-label` and always sends through FluidEmail.
- Detection: Crawl diff on form pages shows changed label classes. A test submit shows a changed mail layout. `grep -rn "form-label\|FluidEmail\|EmailFinisher" <own-extension-paths>` lists overrides.
- Fix: Adapt own form templates and mail templates to the new markup. Approve the label class change in the expect file. Check form definitions and finisher options against the new rendering.
- Proof: Every form fills, validates with clear messages and stores its row. Confirmation and notification mails arrive in Mailpit and look as before (`verification.md` `## CLI gates`).
- Stage: C+D
- Status: practice
- Changelog: none listed

### PHP 8.1 minimum
- Symptom: Composer refuses the jump or code fails at runtime on PHP 7.4 or 8.0.
- Detection: Read the PHP version from the DDEV config, the Composer platform setting and the live system. The live system decides the go-live target.
- Fix: Switch DDEV to PHP 8.1 or newer in stage A, on the old TYPO3 version and before the core jump. Fix PHP code that breaks on 8.1 in stage B. Also read `database.md` for the DB server version, which changes in the same stage.
- Proof: The stage A crawl diff against the previous baseline is 0. `php -l` passes on own code (check command). The error log has no new lines.
- Stage: A
- Status: practice
- Changelog: none listed
