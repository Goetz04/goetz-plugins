# TYPO3 12 to 13

Read this file for every stage group of the rung 12 to 13 (A, B, C+D, E). The target is TYPO3 13.4. TYPO3 13 needs PHP 8.2 or newer. Binding rules (command classes, snapshots, folders, outcomes) live in `process.md`. Topic knowledge lives in `database.md`, `composer.md`, `schema-and-wizards.md` and `verification.md`. This file lists only the pitfalls of this rung.

## How to verify facts

With the MCP (`roadmap.md` says `available`), use `typo3_changelog_lookup` with the version and type filters for a deprecation sweep of the major. Without the MCP, read the TYPO3 core changelog on docs.typo3.org. Facts that you did not confirm in one of these sources stay `unverified`.

Items below carry `Status: practice` when a real upgrade from 11 to 14 used them. No item names a changelog number yet. Add one only after you confirmed it with the MCP or on docs.typo3.org.

### addPageTSConfig deprecated
- Symptom: The deprecation log lists `ExtensionManagementUtility::addPageTSConfig` calls. The page TSconfig order can change after a move.
- Detection: `grep -rn "addPageTSConfig" <own-extension-paths>`. The deprecation log names the origin extension.
- Fix: Move the TSconfig into `Configuration/page.tsconfig` of the extension. TYPO3 loads these files in package order, so check the order against the old load order. Do it in stage B where the old version accepts it.
- Proof: A flat TSconfig dump before and after shows no difference (`ts-dump.php`, `verification.md`). The deprecation log has no entry for it.
- Stage: B
- Status: practice
- Changelog: none listed

### Import wildcards and file extensions
- Symptom: TypoScript or TSconfig loads in a different order or not at all after the move to new file extensions.
- Detection: `grep -rn "@import" <typoscript-paths>` and look for wildcards. List files with the extensions `.ts` and `.txt`. `@import` wildcards sort alphabetically.
- Fix: Rename `.ts` and `.txt` files to `.typoscript` and `.tsconfig`. Rename files so that the alphabetical order gives the old order, or import them one by one. Rename in stage B, one cause per commit.
- Proof: Flat TypoScript and TSconfig dumps before and after the change are equal (`php .typo3-upgrade/tools/ts-dump.php`, `verification.md`). The crawl diff is 0.
- Stage: B
- Status: practice
- Changelog: none listed

### Site config keys deprecated
- Symptom: The deprecation log lists site configuration keys. The language setup of a site can break after a later removal.
- Detection: `grep -rn "iso-639-1\|direction\|typo3Language" config/sites`. The path of the site config folder comes from `inventory.md`.
- Fix: Replace the keys as the changelog of the major states (use `typo3_changelog_lookup` or docs.typo3.org). Site config edits are main session commands when the files are not tracked.
- Proof: The deprecation log has no entry for the keys. The language switch and the `hreflang` output in the crawl diff stay equal.
- Stage: B
- Status: practice
- Changelog: none listed

### Site Set only extensions
- Symptom: A site that includes TypoScript through static includes loses configuration, because an updated extension ships its TypoScript only as a Site Set. Example: form finisher presets go missing and the form throws `FinisherPresetNotFoundException`.
- Detection: After the jump, submit each form (check with a test submit) and read the error log. Compare the extension's current package with its old version for a missing static include.
- Fix: Register the missing YAML configuration manually in the site setup, or switch the site to Site Sets. Choose per extension and write the choice into the step notes.
- Proof: Every form submits, stores its row and sends its mail (`verification.md` `## CLI gates`). The error log shows no new lines.
- Stage: C+D
- Status: practice
- Changelog: none listed

### Rendering changes in the output
- Symptom: The crawl diff shows `twitter:card` missing on pages and `data-list-item-id` attributes on every `<li>` of RTE lists.
- Detection: `residual.py` against the previous baseline. Its normalizer already drops the `twitter:card` default. The `data-list-item-id` attribute comes from CKEditor and appears in stored and rendered content.
- Fix: Approve both effects in the expect file of the step (`process.md` `## Expect file`). Do not patch the output. If a page needs `twitter:card`, set it explicitly in its own meta configuration.
- Proof: `residual.py` reports no unmatched difference besides the approved lines.
- Stage: C+D
- Status: practice
- Changelog: none listed

### PHP 8.2 and DBAL 4
- Symptom: Composer refuses the jump on PHP 8.1. The schema run needs two passes after the jump, because DBAL 4 compares the default charset of tables.
- Detection: Read the PHP version from the DDEV config, the Composer platform setting and the live system. After the jump, run `database:updateschema "*" --dry-run` (check command) and read it again after the first `*.change` run.
- Fix: Switch DDEV to PHP 8.2 or newer in stage A. For the two schema passes and the collation settings, follow `database.md` (sections `DBAL 4 on TYPO3 13` and `Default collation of MySQL 8`). The key `tableoptions` is deprecated, use `defaultTableOptions`.
- Proof: `database:updateschema "*.change" --dry-run` returns an empty list. The stage A crawl diff is 0.
- Stage: A
- Status: practice
- Changelog: none listed

### cms-t3editor and cms-about leave composer.json
- Symptom: Composer cannot resolve the jump, because `typo3/cms-t3editor` and `typo3/cms-about` have no release for the target.
- Detection: `grep -n "cms-t3editor\|cms-about" composer.json`
- Fix: Remove both packages from `composer.json` before the jump. Composer commands are main session commands and run with `--no-scripts` (`composer.md`). The core merged or removed these packages.
- Proof: The Composer jump resolves. `composer.lock` lists neither package. The backend works without them.
- Stage: C+D
- Status: practice
- Changelog: none listed
